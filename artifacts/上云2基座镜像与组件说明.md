## 四 版本核对与维护参考

核对某个组件时，先按容器名称找到正在使用的完整镜像引用，再对照附录中的 ID 与大小。数字构建号、带 _s 的标签、语义版本号和时间戳标签均按原样保留；不得把不同组件的标签数值大小解释为统一的发布先后关系。目录名 cloudApi2_3.1 表示本机部署目录命名，不能单独作为产品发布版本的证明。

MinIO、mc、NTP 和 kubectl 使用 latest 标签。后续做可复现交付时，建议同时记录 RepoDigest；本清单中的短镜像 ID 可用于本机识别，但不替代跨环境拉取时使用的摘要。

如需清理未引用镜像，应先核对安装包、升级回滚要求、按需函数和其他运行时的引用情况。本文件仅记录资产与状态，不包含镜像删除、组件升级或服务重启操作。

### 只读复核命令

```bash
sudo docker image ls --digests --no-trunc
sudo docker ps -a --format "{{.Names}} | {{.Image}} | {{.Status}}"
sudo docker image inspect <image:tag> --format "{{json .RepoDigests}}"
sudo docker system df -v
```

复核命令适用于有相应读取权限的服务器会话。统计口径仍以同一次采集的镜像列表和容器列表为准，避免把不同时间点的数据直接比较。

# 上云2基座数据库用途说明

主机 192.168.76.129　｜　面向开发排查与运维交接

这套基座把数据分在四个数据库实例中。MySQL 主要保存设备、组织、项目和部分直播配置；PostgreSQL 16 承担任务、调度、控制与部分直播业务；PostGIS 保存文件业务元数据及空间相关数据；TimescaleDB 保存按时间组织的轨迹点。定位数据时，应同时确认实例名称、库名和数据表。

## MySQL 中的业务库

MySQL 主要承载平台基础管理和设备接入。部分同名或相似库中存在重复的组织、设备、权限表，不能据此认定它们可以互换。

| --- | --- | --- |

| es310_management_service | 64 | 平台组织与项目管理。organizations、org_members、projects、prj_members、roles、permissions、users 表支持组织、成员、项目和权限；另有设备、告警、邀请与 SSO 配置。 |

| pf_device_service | 66 | 设备管理与服务保障。devices、device_configs、firmwares、device_reports 等记录设备及配置；device_maintenance、device_warranty、maintenance_order 等支持保养、保修和维保工单。 |

| ThingAccessService | 18 | 设备接入层。devices、device_models、device_topos、properties、commands、shadows、rules、jobs 等对应设备模型、拓扑、属性、指令、设备影子与规则。 |

| live_service | 11 | 直播通道和媒体处理管理。channels、configs、cmds、events、records、snapshot_tasks、video_converter_tasks 对应通道、控制事件、录像、截图与转码任务。 |

| ApolloConfigDB | 19 | Apollo 配置中心的配置与发布数据。App、Cluster、Namespace、Item、Release、ReleaseHistory、Instance 等保存应用、命名空间、配置项、发布与客户端实例信息。 |

## PostGIS 中的业务库和模板库

PostGIS 是 PostgreSQL 的空间扩展，可存储几何对象并执行空间查询。本实例 PostgreSQL 版本为 10.23，业务库通常安装 PostGIS 3.2.3；其中 file_storage 同时承担大量文件业务元数据管理。

| 业务库 | 表数 | 用途和结构依据 |

| --- | --- | --- |

| file_storage | 37 | 文件与素材元数据主库。files、objects、media_files、model_files、wayline_files、upload_managers、drives、project_spaces 等支持文件对象、照片视频、模型、航线文件、上传及项目空间；还包括回收站、收藏、对比与视频处理任务。 |

| digital_elevation_data_service | 8 | 高程和地形数据管理。demtile、tifs、tif_files、tif_slices、tif_slices_256、tif_statuses 等管理 DEM 瓦片、TIF 文件和切片状态。安装 PostGIS Raster 3.2.3。 |

| es_flysafe | 4 | 飞行安全空间数据。static_db_area、static_db_plot、db_version、version 支持静态区域或地块及版本管理；具体限制规则应结合服务接口确认。 |

| geo_resource | 5 | 空间资源结构。elements、layers、resources、jobs、migrations 保存元素、图层、资源与处理任务，安装 PostGIS 和 btree_gist。与 PostgreSQL 16 的同名库分别保存独立数据。 |

### 已观察到的业务客户端

file-storage 与 pf-terra-manage-service 均连接 file_storage，es-flysafe 连接 es_flysafe。高程服务配置文件也指向 postgres_instance_2。由此可见，Terra 服务不一定使用与自己同名的库。

| --- | --- |

| es_reconstruction_service、esds、esws、pf_terra_manage_service | 各库仅观察到 public.spatial_ref_sys，没有业务表。不得仅凭库名认定服务当前在此落库。 |

## TimescaleDB 中的轨迹数据

此实例只有一个非模板库 postgres。与其他两套 PostgreSQL 的 postgres 库不同，这里的 postgres 确实有轨迹业务表，并已启用 TimescaleDB 2.11.2。

| 表名 | 用途 | 主要字段 |

| --- | --- | --- |

| track_meta | 一条轨迹的基本信息和时间范围 | track_id、sn、start_time、end_time |

| track_points | 轨迹点时序数据，已注册为 TimescaleDB 超表 | timestamp、latitude、longitude、height、sn、track_id |

| migrations | 数据库结构迁移记录 | id |

### 轨迹记录之间的关系

track_meta 可按 track_id、设备序列号 sn 和起止时间定位轨迹；track_points 记录对应时间点的经纬度和高度。track_points 是超表，TimescaleDB 会将其管理为按时间分块的数据。

track_id 是两张表共同具备的关联字段，查询前仍应核对唯一性和实际关联规则。当前仅确认字段名和类型，时间展示时区、坐标基准及 height 的高度基准应以业务接口定义为准。

### 飞行数据分别存在哪里

| 问题 | 优先入口 | 说明 |

| --- | --- | --- |

| 这次飞行是什么任务 | PostgreSQL 16 → es_task | 任务定义、飞行记录、回放及轨迹索引等管理信息 |

| 设备某一时刻在哪里 | TimescaleDB → postgres.track_points | 连续的经纬度、高度、时间与设备序列号 |

| 航线文件在哪里管理 | PostGIS → file_storage.wayline_files | 航线文件元数据；任务关联可再查 es_task.task_waylines |

| 照片视频或模型文件在哪里 | PostGIS → file_storage | 媒体、模型、对象与文件元数据；文件实体位置需继续看存储配置 |

这些表之间可能通过任务、文件或轨迹标识关联，但本次未验证跨实例的字段映射与外键约束。跨库拼接数据前应核对业务 ID。

### 如何判断服务实际使用哪个库

先确认 Navicat 连接对应的实例，再根据表名判断数据领域；最后核对服务配置中的数据库地址、库名，以及数据库连接会话。库名和表结构只能说明可能用途，实际会话可以补充当前使用关系。

本说明中的“已观察到连接”来自 MySQL information_schema.PROCESSLIST 和 PostgreSQL pg_stat_activity，再与 docker inspect 返回的容器 IP 对照。会话只是采集时刻的快照。任务调度组件还核对了 Compose 中的 DB_DSN。

### 证据范围

数据库版本来自服务端查询；库与表来自 information_schema、pg_database、pg_tables；扩展来自 pg_extension；轨迹超表来自 timescaledb_information.hypertables；落盘目录来自 docker inspect 挂载信息。用途说明结合代表性表名和已确认的服务连接，不把库名推测等同于实际运行配置。
